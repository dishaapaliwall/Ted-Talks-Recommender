1. The 1-Minute Project Summary (Jab Mam Bole: "Explain your project")

English Pitch:
"Our project is a Two-Stage Hybrid TED Talk Recommendation Engine. Because public video platforms lack individual user clickstream logs, traditional collaborative filtering fails. We solved this using a 2-stage architecture: Stage 1 uses Natural Language Processing (TF-IDF vectorizer + Cosine Similarity) to semantically filter candidate talks matching the user's topic query. Stage 2 applies trained supervised machine learning models—comparing Logistic Regression, a pruned Decision Tree, and an ensemble Random Forest—to predict audience popularity (views above median of 1.36M) and re-rank the candidates. We strictly avoid target leakage by never feeding view count or cosine score into the classifier. Random Forest achieved the best AUC of 0.749, and the complete engine is deployed on Streamlit."

Hinglish me samjho:
"Mam, hamare dataset me user ka watch history ya rating nahi thi, to direct collaborative filtering nahi ho sakti thi. Isliye humne 2-stage system banaya: Pehle stage me TF-IDF se user ke topic se match hone wale talks nikaale. Fir doosre stage me Random Forest, Decision Tree aur Logistic Regression se predict kiya ki kaunsi talk actually high-popularity wali hai aur unhe re-rank kiya. Humne view count ko model ke input me bilkul nahi diya taaki target leakage na ho."

3. High-Frequency Viva Questions (Direct Answers)

Q1. Why didn't you use Collaborative Filtering (User-Item Matrix)?
Collaborative filtering requires explicit user-item interaction data (user IDs, ratings, or watch logs). Our dataset only contains video-level metadata (views, speaker, title, description). Hence, we used content-based semantic retrieval combined with supervised popularity re-ranking.
Hinglish: "Kyunki dataset me alag-alag users ki watch history ya ratings nahi thi, sirf video ka data tha."
Q2. What is Target Leakage, and how did you prevent it?
Target leakage occurs when an input feature contains direct or indirect information about the target variable that would not be available during real-time inference. Here: 1. Our target is_popular was derived from viewedCount. We completely dropped viewedCount from the feature matrix $X$. 2. The TF-IDF cosine similarity used for Stage 1 candidate retrieval is never fed as a feature to the classifier. The models only learn from talk duration, age, topic count, speaker, and context.
Hinglish: "Target viewedCount se bana tha, isliye viewedCount ko features me se hata diya. Aur TF-IDF score bhi classifier ko nahi diya, taaki model cheating na kare."
Q3. Why did you use Median Split instead of Mean Split for popularity?
viewedCount is severely right-skewed (a few viral talks have 70M+ views, pulling the mean up to ~2.1M views). If we used the mean, only ~28% of talks would be labeled popular (class imbalance). The median ($1,362,484$ views) splits the dataset into exact 50% Class 1 and 50% Class 0, creating a balanced dataset without needing SMOTE.
Hinglish: "Views right-skewed the. Mean use karte to 70% talks unpopular ho jaati. Median use karne se exactly 50-50% balanced classes ban gayi."
Q4. Compare the 3 models: Why is Random Forest better than Logistic Regression and Decision Tree?
Model AUC-ROC Accuracy Characteristics / Trade-off
Logistic Regression 0.601 58.2% Linear decision boundary. Cannot capture non-linear relationships (e.g., talks between 12-18 mins perform best; very short or very long talks get fewer views).
Decision Tree 0.722 65.8% Non-linear and interpretable. Pruned with max_depth=10 and min_samples_leaf=50 to prevent overfitting on training data.
Random Forest 0.749 68.4% Ensemble Bagging: Combines 150 de-correlated decision trees with feature subsampling ($\sqrt{d}$). Drastically reduces variance while maintaining low bias.
Hinglish: "Logistic regression fail ho gaya kyunki data me linear boundary nahi thi. Decision tree non-linear tha par single tree me variance hoti hai. Random Forest ne 150 trees ka voting ensemble banaya jisse variance khatam ho gayi aur AUC 0.749 mila."
Q5. What is Bagging and how does Random Forest work?
Bagging stands for Bootstrap Aggregating. 1. Bootstrap: Creates 150 subsets of data by sampling with replacement. 2. Random Feature Subspace: At each node split, it only considers $\sqrt{d}$ random features (de-correlating trees). 3. Aggregating: For probability, it averages the class probabilities of all 150 trees:
P(y=1|x) = (1 / B) * Σ P_b(y=1|x)
Hinglish: "Bootstrap ka matlab random sampling with replacement. 150 alag-alag trees train hote hain aur split karte waqt sirf random features dekhe jaate hain. Final output saare trees ka average hota hai."
Q6. What is TF-IDF and Cosine Similarity in Stage 1?
TF-IDF (Term Frequency - Inverse Document Frequency): Measures how important a word is to a talk relative to the entire corpus.
TF-IDF(t, d) = TF(t, d) * log(N / DF(t))
Cosine Similarity: Calculates the cosine of the angle between the query vector and talk vector:
Cosine Sim(A, B) = (A · B) / (||A|| * ||B||)
Range is 0 (completely unrelated) to 1 (identical topic).
Hinglish: "TF-IDF se words ko importance milti hai (common words jaise 'the', 'is' ka weight drop ho jata hai). Cosine similarity do vectors ke beech ka angle measure karti hai."
Q7. What is 5-Fold Stratified Cross-Validation?
Dataset is divided into 5 equal folds while preserving the 50:50 class proportion in each fold. In each iteration, 4 folds (80%) are used for training and 1 fold (20%) for testing. This is repeated 5 times so every talk is tested once, preventing test-set bias.
Hinglish: "5-Fold CV me pure dataset ko 5 parts me baanta, har baar 4 part pe train aur 1 part pe test kiya. 'Stratified' ka matlab har fold me positive aur negative class ka ratio barabar raha."
Q8. How does your Streamlit deployment work?
The app is built in Python using Streamlit: 1. @st.cache_resource loads the cleaned data, fits the TF-IDF matrix, and trains the models once during startup. 2. Users can enter any search query or click preset buttons. 3. The app displays 4 tabs: Random Forest, Logistic Regression, Decision Tree, and a Side-by-Side Model Consensus Matrix showing if models agree (Full Agreement vs Majority). 4. Users can mark talks as "Watched", which filters them out in real time via Streamlit Session State.
Hinglish: "Streamlit cloud pe deployed hai. Startup pe model cache ho jata hai. User topic search karta hai to real-time me recommendations aate hain aur Consensus matrix me teeno models ka comparison dikhta hai."

4. Quick Formulas Cheat Sheet

  • Sigmoid Function (Logistic Regression): $\sigma(z) = \frac{1}{1 + e^{-z}}$
  • Entropy (Decision Tree): $H(S) = - \sum p_i \log_2(p_i)$
  • Information Gain: $IG(S, A) = H(S) - \sum \frac{|S_v|}{|S|} H(S_v)$
  • StandardScaler: $z = \frac{x - \mu}{\sigma}$
  • Precision: $\frac{TP}{TP + FP}$  |  Recall: $\frac{TP}{TP + FN}$  |  F1: $2 \cdot \frac{P \cdot R}{P + R}$
  • AUC-ROC: Area under True Positive Rate vs False Positive Rate curve across all classification thresholds.
